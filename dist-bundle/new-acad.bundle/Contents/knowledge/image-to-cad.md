# 图片 / 扫描稿 → CAD（2026-09-22 定稿骨架）

> 触发场景：用户给一张图（截图 / 扫描件 / 手绘草图 / 照片）说"画进 CAD / 照着做成图"。

## 0. 总原则（先记这条，比流程重要）

- **现场手绘草图的比例没有信息量**：手绘千奇百怪，只有**文字标注**和**大致形状**可考。
  → 所以**不描像素，抄尺寸**。
- **坐标只来自三处**：图上的尺寸标注 / 用户口述的尺寸 / 用户给的目标总尺寸。
- **像素几何只用于**：识别形状与拓扑（谁连谁、门洞在哪、哪条线对应哪个标注）。
- **读不准就标出来问用户，绝不硬猜**——猜出来的"专业图"比描图更坏。

## 1. 分诊（先判定，再动手；别跳过）

| 图里有什么 | 怎么画 | 产物定位 |
|---|---|---|
| **有尺寸标注** | 路线 B：标注驱动重建 + 尺寸链闭合校验 | 可施工的真尺寸图 |
| **无标注，但有标定线索**（图框比例尺 1:100、网格、坐标标注） | 用线索标定 → 按真实尺寸重建 | 可施工（略降级） |
| **完全没尺寸** | **必问一次**（见 §4）→ 按用户选择：按图比例 / 单点标定 / 目标总尺寸 | 比例图或示意图 |
| **不是工程图**（照片、实物、插画、示意图） | 照形描（traceImage），或按用户给的目标总尺寸缩放 | 示意图，**如实说明**，不假装是施工图 |

## 2. 路线 B：标注驱动重建（标准五步）

1. **读图列尺寸表**（先不画！）
   - 输出结构化的 `dimension-table`（落盘到工作区，供用户/我复核）：
     ```json
     {
       "unit": "mm",
       "scaleHint": null,
       "walls": [{"id": 1, "from": "A", "to": "B", "length": 3600, "label": "3600"}],
       "total": {"x": 8400, "y": 5400},
       "openings": [{"onWall": 3, "width": 900, "offsetFromStart": 1200, "kind": "door"}],
       "uncertain": [{"field": "walls[4].length", "seen": ["1200", "1800"], "why": "手写数字 2/8 难以区分"}]
     }
     ```
2. **尺寸链闭合校验**：分段和 == 总长；不闭合 → 报错并指出哪几段矛盾（手绘稿最常见的病）
3. **不确定项提问**：把 `uncertain` 列给用户，问清再画（**只问真正不确定的，别把整个表丢回去让人重填**）
4. **按表重建**（锚点 + 相对尺寸的写法最稳）
   - 例：以左下角为原点 → `createLineSegment (0,0)-(3600,0)` 外墙底边；`createPolyline` 连续画外轮廓；弧用 `bulges`；门洞用 `offsetEntity` 定位后 `createLineSegment` 断口
   - 顺手可以把标注也画上：`createText` / `dimLinear` / `dimAligned`
5. **自检（必做）**
   - 回读：`getEntitiesByLayer` + 端点坐标，把关键段量一遍，与尺寸表对账
   - 拓扑比对：与"形状骨架"比对——闭环是否闭合、该垂直的垂直、该平行的平行、门洞数与位置是否一致
   - 结果为"形状关系对 + 尺寸来自标注"才算过

## 3. 三道保险（缺一不可）

| 保险 | 做法 | 挡什么 |
|---|---|---|
| 双通道交叉 | 视觉模型读一遍 + OCR 再过一遍，逐项比对 | 手写数字误读 |
| 尺寸链闭合 | 分段和 vs 总长 | 图本身自相矛盾 / 读数错 |
| 不确定项上浮 | 模型必须输出 `uncertain[]`，不许硬猜 | 悄悄猜错（最危险） |

## 4. 无尺寸图的兜底（**只问一次，别反复问**）

问：**"图上有没有哪一段长度你知道？哪怕一个。"** 给三个默认选项：

1. **按图比例画**（默认）——形状准，实际尺寸未知；明确告诉用户这一点
2. **你给一个参考尺寸**（单点标定）：用户报一段长度 → 该段像素长度 → 求 mm/px → **整图缩放到真实单位**（`scaleEntities` 或画的时候直接乘系数）
3. **你给一个目标总尺寸**（如"画成 10 米宽"）→ 按图比例缩放到目标

**反面效应（记住）**：没尺寸时"形状"是唯一可用信息 → 这种图里"去抖动 / 清理线稿"反而更值钱（要忠实于形状），与路线 B 的用法互补。

## 5. 可用工具（插件已有，2026-09-22 核对）

- 画：`createLineSegment` / `createPolyline`（`bulges` 就是圆弧）/ `createCircle` / `createText` / `createMText` / `addLabel`
- 标注：`dimLinear` / `dimAligned` / `dimRadius` / `dimAngular` / `dimDiameter`
- 编辑：`offsetEntity` / `trimEntity` / `extendEntity` / `filletEntities` / `joinEntities` / `moveEntities` / `scaleEntities` / `rotateEntities` / `mirrorEntities` / `copyEntities` / `breakEntity` / `stretchEntity` / `overkillEntities`
- 图层/读回：`createLayer` / `setLayerColor` / `getEntitiesByLayer` / `getEntityInfo`
- 照形描（仅路线 A/示意）：`traceImage`（mode 不传=自动判型；要落地直接 `draw:true`）
