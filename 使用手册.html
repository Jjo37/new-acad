0 这是什么0 What this is

new-acad 是长在 AutoCAD / Civil 3D 面板里的 AI 助手：你用大白话描述要做什么，它直接在你的图纸里画、改、量、导出。

和"网页版 AI"的区别

  • 它在图纸里干活，不是给你一段脚本让你自己粘。
  • 用你自己的模型 Key（任何 OpenAI 兼容的服务商都行；面板给了常见几家的预设，也能填自定义地址），不经过我们的服务器，我们看不到你的图和对话。
  • 可核对：每一步调用了什么方法、花了多久、成功还是失败，面板里都能看到。
  • 可回放：一次干成功的活能存成工作流，下次填几个参数重跑；做错的单步能撤回来。

三步开始

  1. 装：运行安装包，装完在 CAD 里打开面板（见 第 1 章）。
  2. 配：填一个模型 API Key，保存（见 第 2 章）。
  3. 用：选中对象，说"把这些圆往外偏移 50"，它就动手。

先知道这三条边界

不写清楚会踩坑
  • 支持 AutoCAD 2025 / 2026；装了 Civil 3D 2025 / 2026 就多出专业能力。纯 AutoCAD 下路线 / 曲面 / 廊道 / 管网等方法会明确回「需要 Civil 3D」，画图、图层、块、文件读写照常可用。2024 及更早是另一套运行时（.NET Framework 4.8），装不上也用不了。
  • 撤销只对普通 AutoCAD 图元承诺（线、多段线、圆、弧、文字、点、块参照）。Civil 3D 对象（路线 / 曲面 / 廊道 / 管网）会标成"不可撤"，不会假装能撤。
  • 工作流回放不能跨图纸：记录里的"句柄"只在录制那张图里有意义，换图后引用句柄的步骤会被拦下。

new-acad is an AI assistant that lives inside the AutoCAD / Civil 3D palette: you describe the task in plain language and it draws, edits, measures and exports in your drawing.

How it differs from a chat website

  • It works inside the drawing — not a script you paste yourself.
  • Your own model key (any OpenAI-compatible provider; the palette ships presets for a few common ones and accepts a custom endpoint). Nothing goes through our servers; we never see your drawings or your chat.
  • Verifiable: every method call, its duration and its result are visible in the palette.
  • Replayable: a task that worked can be saved as a workflow and re-run with new parameters; a single wrong step can be reverted.

Three steps to start

  1. Install: run the installer, then open the palette inside CAD (see chapter 1).
  2. Configure: paste a model API key and save (see chapter 2).
  3. Use: select objects and say "offset these circles outward by 50".

Three limits worth knowing up front

Read this before you file a bug
  • AutoCAD 2025 / 2026; add Civil 3D 2025 / 2026 for the civil toolkit. On plain AutoCAD, alignment / surface / corridor / pipe-network methods answer "Civil 3D required" explicitly, while drafting, layers, blocks and file I/O work as usual. 2024 and earlier run on a different runtime (.NET Framework 4.8); the plugin will not load.
  • Undo only promises plain AutoCAD entities (line, polyline, circle, arc, text, point, block reference). Civil 3D objects (alignment / surface / corridor / pipe network) are marked "cannot be reverted" instead of pretending.
  • A recorded workflow cannot be replayed in another drawing: the handles only mean something in the file they were recorded in.

1 安装与卸载1 Install & uninstall

1.1 系统要求

项目要求
操作系统Windows 10 / 11（64 位）
CADAutodesk AutoCAD 2025 或 2026（正版，自行准备）；装了 Civil 3D 2025 / 2026 则额外获得路线 / 曲面 / 廊道 / 管网等专业能力
权限安装需要管理员（默认装到 C:\Program Files\new-acad）
磁盘约 300 MB（含内置 Node 运行时与离线手册）
网络需要能访问你选的那家模型服务；不需要连我们的服务器
Civil 3D 2024 及更早：不支持 插件用 .NET 8 构建，2024 及更早的 AutoCAD 仍是 .NET Framework 4.8，程序集不兼容。装上去也会加载失败。

1.2 安装（4 步）

  1. 下载安装包 new-acad-setup-v1.12.0.exe（或绿色版 zip）。
  2. 双击运行，允许管理员权限。安装向导支持中文 / English。
  3. 走完向导。装完会调用 install.ps1：检测 AutoCAD / Civil 3D 版本、注册插件自启、引导你填 AI 配置。
  4. 完成。勾选"打开使用手册"会打开本文件；随后启动 AutoCAD 或 Civil 3D。
装完怎么确认成功 启动 CAD，命令行输入 HANK_SHOW。面板能弹出、状态显示「● 就绪」，就是装好了。

1.3 静默安装（企业 / 批量部署）

new-acad-setup-v1.12.0.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART

静默安装会跳过配置向导 向导被跳过（skipifsilent），所以不会自动检测 CAD、不会写配置。装完需要人工打开面板填 Key，或直接预置 config.json（字段见 第 3 章）。

1.4 升级

  • 直接运行新版安装包覆盖安装，不需要先卸载。
  • 升级前建议备份 config.json（里面是你的 Key、模型、项目设置）。
  • 升级后重启 CAD（插件 DLL 被占用时无法替换，安装器会提示）。

1.5 卸载

  1. 先关掉 CAD（插件 DLL 运行中被锁定，不关会卸不干净）。
  2. Windows「设置 → 应用 → 已安装的应用」找到 new-acad，卸载。
  3. 或运行安装目录下的 uninstall.bat。

卸载会删：程序目录、插件注册、自启项、运行日志、消息队列文件。

卸载不会删（这是故意的）
  • exchange\ 下的项目、工作流记录、导出文件 —— 那是你的成果。
  • %LOCALAPPDATA%\Civil3DMcpPlugin\plugin.log（排查问题用）。
  • %APPDATA%\Autodesk\ApplicationPlugins\new-acad.bundle（彻底清理时手动删）。

1.1 Requirements

ItemRequirement
OSWindows 10 / 11 (64-bit)
CADAutodesk AutoCAD 2025 or 2026 (licensed copy). With Civil 3D 2025 / 2026 installed you also get alignments / surfaces / corridors / pipe networks
PrivilegesAdministrator to install (defaults to C:\Program Files\new-acad)
Disk~300 MB (bundled Node runtime and offline manual)
NetworkMust reach the model provider you choose; no connection to our servers needed
Civil 3D 2024 and earlier: not supported The plugin targets .NET 8; AutoCAD 2024 and older still run on .NET Framework 4.8. The assemblies are incompatible.

1.2 Install (4 steps)

  1. Download new-acad-setup-v1.12.0.exe (or the portable zip).
  2. Run it and allow administrator rights. The wizard speaks Chinese and English.
  3. Finish the wizard. It runs install.ps1: detect AutoCAD / Civil 3D, register autoload, guide you through the AI settings.
  4. Done. Tick "open the manual" and start AutoCAD or Civil 3D.
How to confirm it worked Start CAD and type HANK_SHOW. If the palette opens and the status reads "● Ready", you are set.

1.3 Silent install (enterprise)

new-acad-setup-v1.12.0.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART

Silent install skips the setup wizard Because of skipifsilent it does not detect Civil 3D and does not write configuration. Fill in the key from the palette afterwards, or pre-seed config.json (fields in chapter 3).

1.4 Upgrade

  • Run the newer installer over the old one — no need to uninstall first.
  • Back up config.json first (key, model, project settings).
  • Restart CAD afterwards; the installer warns if the plugin DLL is locked.

1.5 Uninstall

  1. Close CAD first (the plugin DLL is locked while it runs).
  2. Windows "Settings → Apps" → new-acad → Uninstall.
  3. Or run uninstall.bat in the install folder.

Removed: program files, plugin registration, autostart entry, runtime logs, message queue files.

Not removed (on purpose)
  • exchange\ — your projects, workflow records and exported files: your work.
  • %LOCALAPPDATA%\Civil3DMcpPlugin\plugin.log.
  • %APPDATA%\Autodesk\ApplicationPlugins\new-acad.bundle (delete by hand for a clean sweep).

2 首次配置2 First-time setup

2.1 先准备一个模型 API Key

你的情况填什么备注
已经有某家的账号那家的 OpenAI 兼容地址面板下拉里给了常见几家的预设；地址以各家官方文档为准
用公司统一采购的服务网关 / 代理暴露的 OpenAI 兼容地址同上，Key 用你账号的
自建或上面都没有任何 OpenAI 兼容端点填地址 + Key + 模型名

用哪家只看三件你自己的事：已有账号、你所在网络能否直接访问、团队对成本的要求。本手册不对服务商做推荐，也不对第三方服务的价格与可用性做任何承诺——面板里预设的顺序只是界面顺序，不代表优先级。

2.2 在面板里填六项

控件填什么建议
项目名可选。填了就把对话、工作流记录、导出文件按项目隔离按工程名建，找东西方便
界面语言自动 / 中文 / English自动 = 跟随系统
选择模型（服务商）下拉选一家—
模型该家下面可用的模型名不确定就用默认
Key粘贴你的 API Key点「显示」核对；点「清除」抹掉
操作上限一次任务最多跑几步（0 = 不限）默认够用；怕跑飞就设 40

填完点 保存，状态行会显示「● 已保存」。

2.3 保存后自检（三步）

  1. 看状态灯：状态栏显示「● 就绪」＝ 内置服务在跑。
  2. 点「端口」：确认三个端口都在（插件 8080 / MCP 3000 / 服务 19876）。
  3. 发一句话：随便问"现在这张图有几个对象"。能回话就说明 Key 和网络都通了。

2.4 换服务商 / 换模型

  • 换完记得再点一次保存，然后点「重启服务」让它生效。
  • 换了模型如果答非所问、频繁调错方法，多半是模型能力不够——换回上一家即可。

2.5 项目文件夹（多工程隔离）

配置区的「项目名」不是摆设：填了项目名，这个工程的对话记录、工作流记录、AI 写出的文件都会单独放在 exchange\projects\<项目名>\ 下，和别的工程互不干扰。

  • 建立：输入名字 → 点「建立」，自动建目录并切过去。
  • 打开：在资源管理器里定位到该项目文件夹。
  • 清理：删掉整个项目目录（不可恢复，会二次确认）。
  • 不填 = 全局模式，所有记录混在一处；只做一个工程的话这样也行。

2.6 界面语言

配置区「界面语言」三档：自动（跟随系统） / 中文 / English。切换后面板重建一次（对话内容保留）。

它只管界面文案；AI 用什么语言回答跟着你最近一句话走（你说中文它就说中文）。

2.7 清除配置 / 换 Key

  • 显示：把 Key 显示成明文，核对用；核对完别截图外传。
  • 清除配置：抹掉面板里保存的服务商 / 模型 / Key（会二次确认）。换机器、换账号时用。
  • Key 是明文存在本机 config.json 里的，卸载不会自动删（见 3.5）。

2.8 AI 长期记忆

AI 会把「这张图定过什么口径、你常用的做法」记在长期记忆文件里，下次开工不用重讲。

  • 位置：server\memory\agent-memory.md（项目模式下按项目分开）。
  • 查看 / 编辑：面板「更多 → 查看 AI 记忆」。
  • 想让它忘掉：清空那个文件，或用「更多 → 全部清理」。
  • 长期记忆是本地文件，不会上传到任何地方。

2.1 Get a model API key first

Your situationWhat to fill inNotes
You already have an account somewhereThat vendor's OpenAI-compatible URLThe palette ships presets for a few common ones; follow each vendor's own docs for the exact URL
You use a company-purchased serviceThe OpenAI-compatible URL your gateway / proxy exposesSame idea; the key is your own
Self-hosted, or none of the aboveAny OpenAI-compatible endpointURL + key + model name

Which provider to use depends on your own situation: the account you already have, whether your network can reach it, and what your team wants to spend. This manual does not recommend a vendor and makes no promise about a third party's pricing or availability — the order of presets in the palette is UI order, not priority.

2.2 Six fields in the palette

ControlWhat to putSuggestion
ProjectOptional. Isolates chat, workflow records and exports per projectName it after the job
LanguageAutomatic / Chinese / EnglishAutomatic follows Windows
ProviderPick one—
ModelA model available under that providerKeep the default if unsure
KeyPaste your API key"Show" to verify, "Clear" to wipe
Step limitMax steps per task (0 = unlimited)Default is fine; 40 if you want a leash

Press Save; the status line shows "● Saved".

2.3 Three-step self check

  1. Status light: "● Ready" means the built-in service is running.
  2. Press "Ports": all three should listen (plugin 8080 / MCP 3000 / service 19876).
  3. Send a question: try "how many objects are in this drawing". An answer means key and network are fine.

2.4 Switching provider or model

  • Save again, then press "Restart" so it takes effect.
  • If a model misses the point or calls the wrong methods, it is usually model capability — switch back.

2.5 Project folder (one folder per job)

The "Project" field is not decoration: with a project name, the chat history, workflow records and any file the AI writes stay under exchange\projects\<name>\, isolated from other jobs.

  • Create: type a name, press "Create" — the folder is made and selected.
  • Open: opens that folder in Explorer.
  • Clear: deletes the whole project folder (irreversible, asks twice).
  • Empty = global mode; everything lands in one place. Fine for a single job.

2.6 Interface language

Three choices: Automatic (follow Windows) / Chinese / English. Switching rebuilds the palette once; the conversation is kept.

This only affects UI wording. The AI answers in the language of your latest message.

2.7 Clearing the settings / changing the key

  • Show: reveals the key in plain text for verification — do not screenshot it.
  • Clear settings: wipes provider / model / key from the palette (asks twice).
  • The key sits in plain text in config.json on this machine; uninstalling does not delete it (see 3.5).

2.8 AI long-term memory

The AI keeps a long-term memory file — conventions agreed for this drawing, the way you usually work — so you do not repeat yourself every session.

  • Location: server\memory\agent-memory.md (per project in project mode).
  • View / edit: "More → View AI memory".
  • To make it forget: empty the file, or "More → Clean everything".
  • It is a local file; nothing is uploaded.

4 面板功能逐项4 Every control, one by one

每条都按同一体例：作用 / 会发生什么 / 别这么用。按界面从上到下、从外到内排列。

4.1 状态栏（面板最下面一行）

状态灯左下角

  • 作用：一眼看内置服务是否活着。
  • 会看到：「● 就绪」= 正常；「● 离线」= 服务没起来；「● 异常」= 起过但崩了；「思考中」「排队中」「在线」「已回复」是任务状态。
  • 别这么用：看到「离线」别反复重启 CAD，先点「端口」看是不是服务没起。

折叠 ▲状态栏最右

  • 作用：把配置区收起来，只留对话区和输入框。
  • 会发生什么：只是视觉折叠，配置不改。

重启服务状态栏右侧

  • 作用：重启内置 AI 服务（relay）。改完配置不生效、服务卡住时用。
  • 会发生什么：面板短暂断开 3~10 秒；对话和任务计划都保留。
  • 别这么用：正在跑长任务时按，当前任务会中断。

端口状态栏右侧

  • 作用：打开「端口状态诊断」，列出三个端口的真实占用情况。
  • 会看到：每行是 [✓/✗] 端口 服务名 PID（程序名）；若端口被别的程序占了，会标「← 被其他程序占用！」。
  • 三个按钮：刷新 重新探测 · 复制诊断 把整段结果拷到剪贴板（发给支持时用）· 打开配置向导 改端口后重新走一遍配置。
  • 别这么用：端口冲突时不要硬改 config.json 后不重启，改完必须重启服务。

工具状态栏右侧

  • 作用：把消息区切成「工具页签」（看 AI 到底调了什么）。再点一次切回对话。
  • 会发生什么：只替换消息区，输入框和配置区留着——可以边看调用边说话。
  • 注意：第一次打开会落在「工作流记录」视图，用页签左上角的按钮可切到「调用流 / 方法目录」。

调用流状态栏右侧

  • 作用：一步到位打开「调用流」视图——就是带通道列那张表（能看到走的是 tcp 还是 mcp）。
  • 会看到：`时间 / 方法 / 通道 / 耗时 / 字符 / 状态`。状态列里 `✓` 成功、`▶` 进行中、`✗ -32602` 这类是失败码；无逆操作的动作会追加「· 不可撤」。
  • 注意：表里是本次 CAD 会话的完整流水，关掉面板不会清；想清点「清空」（见 4.4）。

4.2 配置区（对话区上方）

项目名 + 打开 / 建立 / 清理配置区第一行

  • 作用：把这次工程的对话、工作流记录、AI 写出的文件装进一个独立文件夹。
  • 会发生什么：「建立」→ 建 exchange\projects\<名字>\ 并切过去；「打开」→ 资源管理器定位；「清理」→ 删整个项目目录（不可恢复，二次确认）。
  • 别这么用：清理前先确认里面没有你要留的工作流记录和导出文件。

界面语言配置区

  • 作用：切面板文案：自动（跟随系统）/ 中文 / English。
  • 会发生什么：面板立即重建（约 1 秒），对话内容保留。
  • 注意：它不改 AI 的回复语言——那个跟着你最近一句话走。

选择模型（服务商）/ 模型配置区

  • 作用：选哪家的哪个模型来干活。
  • 会发生什么：选了服务商会自动拉该家可用模型列表；切模型后需要保存 + 重启服务才生效。
  • 别这么用：模型太小（参数少）时会频繁调错方法，看着像"插件坏了"，其实是模型不够用。

Key + 显示 / 清除配置配置区

  • 作用：「显示」把 Key 变明文核对；「清除配置」抹掉服务商/模型/Key。
  • 会发生什么：清除会二次确认；清完必须重新填才能用。
  • 别这么用：显示状态下截图——那是明文 Key，等于把账号给出去了。

操作上限（步数）配置区

  • 作用：一次任务里 AI 最多能连续执行多少步。
  • 取值：0 = 不限（一直干到完成）；填正数就是硬上限。
  • 别这么用：设得太小（比如 5）会导致复杂任务"干到一半说没步骤了"。默认值够用。

保存配置区

  • 作用：把这一屏设置写进 config.json 并通知服务。
  • 会发生什么：状态行显示「● 已保存」；不点保存，改了也不生效。

4.3 对话与输入区

输入框 + 发送底部

  • 作用：用大白话下指令。Enter 发送，Esc 不会把面板收起来（这是故意的，防止误触）。
  • 会发生什么：发送后状态变「思考中」，工具页签里能看到它一步步在调方法。
  • 别这么用：一句话塞三件事。拆开说，出问题好定位。

上传文件底部按钮行

  • 作用：把一个本地文件的路径交给 AI，让它自己读（Excel / Word / PDF / 图片 / 文本都可）。
  • 会发生什么：路径插进输入框；你可以补一句说明再发送。
  • 注意：不是"粘贴图片"，是给路径；AI 读文件受安全边界限制（见第 6 章）。

取消任务底部按钮行

  • 作用：停掉当前正在执行的任务，保留任务计划（下次能接着干）。
  • 会发生什么：AI 当前那一步结束后停下，不再继续下一步。

清空会话底部按钮行

  • 作用：清掉当前作用域的聊天记录，保留任务计划。
  • 会发生什么：弹一次确认（显示要删多少条）；不可恢复。
  • 别这么用：想"忘掉刚才那段对话"用它；想"放弃这个任务"用「清空任务」。

清空任务底部按钮行

  • 作用：放弃任务计划（activePlan），不动聊天记录。
  • 三者区别：取消任务=停执行留计划 · 清空会话=清聊天留计划 · 清空任务=丢计划。

更多底部按钮行

  • 作用：一个菜单，装的是不常用但要有入口的东西。
  • 菜单项： 打开知识库文件夹（看内置/用户知识库在哪）· 知识源设置（只读引用）（把你的规范/资料文件夹挂进来，只读不改你的文件）· 打开配置文件（高级）· 查看 AI 记忆（长期记忆文件）· 使用手册（打开安装目录里的这份文档）· 清理日志 / 清理缓存（选择集、跨图缓存）/ 清理 MISSING 报告 / 全部清理。
  • 别这么用：「全部清理」会连任务计划一起清（长期记忆和知识库保留），先确认。

4.4 工具页签（点「工具」或「调用流」进来）

这里看 AI 干了什么、把干成功的活存下来重跑、把做错的一步撤回来。

模式按钮（左上角）工具页签

  • 作用：在三个视图间循环：调用流 → 方法目录 → 工作流。按钮上写的是"点一下会切到哪个"。
  • 注意：日志视图是单独入口（下面「撤回上次」），不在这条循环里。

搜索 / 只看失败工具页签工具栏

  • 作用：调用流里按方法名过滤；「只看失败」只留出错的调用。
  • 用途：任务跑歪了，先点「只看失败」，一眼看到哪一步挂的。

清空工具页签工具栏

  • 作用：按当前视图变化：调用流=清空调用流水（同时清服务端缓存的事件，重连不会回来）；工作流=把记录移到 _trash（可恢复）；日志=「清理失效」只清撤不回的条目；回放中=「停止」。
  • 别这么用：调用流的「清空」是清显示记录，不动图纸。

导出工作流视图

  • 作用：把选中的工作流记录导出成 JSON + Markdown（便于存档、同事之间传）。
  • 会发生什么：写到 exchange\export\，状态行显示路径。

回放 / 批准 / 开始回放工作流视图，一个按钮三种含义

  • 作用：把一条记录重新跑一遍。
  • 三种状态：空闲时叫「回放」→ 进入计划视图；有绑定表没填时叫「开始回放」；回放过程中叫「批准」，每点一次执行下一步。
  • 为什么逐步批准：删除类动作（C 档）永远一步一确认，不给"批量放行"。
  • 别这么用：不能跨图纸回放。换图后引用旧句柄的步骤会被拦下并提示两张图的文件名。

绑定表（改参数重放）工作流视图

  • 作用：把记录里的数值/名称抽成"槽位"，改完再跑一遍。
  • 会看到：`槽位 / 类型 / 值 / 说明`，值那一列可以直接编辑。
  • 规则：同值同键会自动合并（改一处，六步全变）；空着不填会被阻断，不会偷偷用旧值；句柄不会成为槽位（那是对象绑定，不是参数）。

计划视图回放中

  • 作用：看这一步一步要怎么走。
  • 会看到：`步 / 方法 / 档 / 参数 / 状态`。A 档只读、B 档可逆写、C 档破坏性（红色）；下一行标「待确认」。
  • 会发生什么：点「批准」才执行一步；失败立即停，不再往下跑。

撤回上次工具页签工具栏

  • 作用：打开「动作账本」（日志视图），可以看到本次会话每个动作、并单独撤回某一条。
  • 会看到：`序号 / 时间 / 干了什么 / 可撤 / 状态`。「可撤/不可撤/已失效」鼠标悬停会给原因。
  • 右键菜单：撤回这一条 · 清理撤不回的记录 · 清空回退清单（后者要点两次确认，8 秒内有效）。
  • 边界：只对普通 AutoCAD 图元承诺；换图纸清空账本；一条动作撤了不影响旁边的动作。

4.1 Status bar (bottom row)

Status lightbottom-left

  • What: at a glance, is the built-in service alive.
  • You see: "● Ready" = fine; "● Offline" = service not running; "● Error" = it started and died; "Thinking", "Queued", "Online", "Replied" are task states.
  • Do not: restart Civil 3D repeatedly on "Offline" — press "Ports" first.

Collapse ▲far right

  • What: folds the settings area away, leaving chat and input.
  • Happens: visual only; nothing is changed.

Restartright side

  • What: restarts the built-in AI service (relay). Use it when a config change did not take effect or the service is stuck.
  • Happens: the palette drops for 3–10 seconds; chat and the task plan are kept.
  • Do not: press it while a long task is running — that task is interrupted.

Portsright side

  • What: opens "Port status" listing the three ports and who really holds them.
  • You see: [✓/✗] port service PID (process); a port taken by another program is flagged "taken by another program!".
  • Three buttons: Refresh · Copy diagnosis (paste into a support message) · Open Setup Wizard.
  • Do not: edit config.json ports and forget to restart the service.

Toolsright side

  • What: swaps the message area for the tools pane (what the AI actually called). Press again to go back.
  • Happens: only the message area is replaced — input and settings stay, so you can chat while watching calls.
  • Note: the first open lands on workflow records; the mode button at the top-left cycles to call stream / catalog.

Call streamright side

  • What: opens the call-stream view directly — the table with the Via column (tcp vs mcp).
  • You see: `Time / Method / Via / Took / Chars / Status`. Status shows `✓` ok, `▶` running, `✗ -32602` style failures; steps with no inverse are tagged "no undo".
  • Note: it lists this CAD session's calls; closing the pane does not clear it. Use "Clear" (see 4.4).

4.2 Settings (above the chat)

Project + Open / Create / Clearfirst row

  • What: keep this job's chat, workflow records and AI-written files in one folder.
  • Happens: Create makes exchange\projects\<name>\ and switches to it; Open shows it in Explorer; Clear deletes it (irreversible, asks twice).

Languagesettings

  • What: Automatic (follow Windows) / Chinese / English.
  • Happens: the palette rebuilds (~1 s); the conversation is kept.

Provider / Modelsettings

  • What: which vendor and which model does the work.
  • Happens: picking a provider loads its model list; after switching, Save then Restart.

Savesettings

  • What: writes this screen into config.json and tells the service.

  • Items: Open knowledge folder · Knowledge sources (read-only) — mount your standards folder, nothing is modified · Open config file · View AI memory · User Guide (opens this document from the install folder) · Clean logs / Clean cache (selection, cross-drawing) / Clean MISSING reports / Clean everything.

4.4 Tools pane (via "Tools" or "Call stream")

Where you see what the AI did, save a task that worked, and revert a single wrong step.

Mode button (top-left)tools pane

  • What: cycles three views: call stream → method catalog → workflows. The label says where the next click goes.
  • Note: the journal has its own entry ("Undo last"), it is not in this cycle.

Search / Failed onlytools toolbar

  • What: filter the call stream by method name; "Failed only" keeps errors.
  • Use it: when a task goes wrong, hit "Failed only" and look at the one step that broke.

Cleartools toolbar

  • What: behaves per view — call stream: clears the session call log (and the service-side event buffer, so a reconnect does not bring it back); workflows: moves records to _trash; journal: "Clear stale" prunes entries that can never be reverted; during replay: "Stop".
  • Do not: expect it to touch the drawing — it only clears records.

Exportworkflow view

  • What: exports the selected workflow as JSON + Markdown (archive it, hand it to a colleague).
  • Happens: written to exchange\export\; the status line shows the path.

Replay / Approve / Start replayone button, three meanings

  • What: runs a record again.
  • States: idle = "Replay" (opens the plan); binding table open = "Start replay"; during replay = "Approve", one click per step.
  • Why step by step: destructive steps (tier C) always need a per-step confirmation — there is no batch approval for them.
  • Do not: replay across drawings. Steps using handles from the recorded file are blocked, and the message names both files.

Binding table (re-run with new parameters)workflow view

  • What: turns numbers/names in the record into slots you can edit before re-running.
  • You see: `slot / type / value / note`; the value column is editable.
  • Rules: identical values collapse into one slot (change once, all six steps follow); an empty slot blocks the run instead of silently reusing the old value; handles never become slots.

Plan viewduring replay

  • What: shows how the replay will proceed.
  • You see: `step / method / tier / params / state`; A = read-only, B = reversible write, C = destructive (red); the next row is marked "needs confirmation".
  • Happens: each "Approve" runs exactly one step; a failure stops the run immediately.

Undo lasttools toolbar

  • What: opens the action journal, where each action can be reverted on its own.
  • You see: `# / time / what it did / undoable / state`; hovering a blocked row explains why.
  • Right-click: Revert this step · Clear entries that cannot be reverted · Clear the whole journal (the last one needs two clicks within 8 seconds).
  • Limits: plain AutoCAD entities only; switching drawings clears the journal; reverting one step never touches its neighbours.

5 典型场景5 Typical tasks

5.1 画一张图：从选中到成图

  1. 在 CAD 里选中对象（或者不选，让它自己按条件找）。
  2. 说：「把这些多段线的每个节点画一个直径 100 的圆」。
  3. 看工具页签：它会先 `getSelection` → 读顶点 → 逐个 `createCircle`。
  4. 不满意就让它改：「直径改成 60」——它会重画或改属性。

5.2 按图层批量处理

「把 GC-DGX 图层上的高程点全部改成颜色 3，并把 z=0 的挑出来告诉我」。
它会用 analyzeLayer 先看这一层长什么样，再决定过滤条件——比你自己一个个点快。

5.3 出量

「统计这个曲面的面积、最大最小高程」·「把这些线的总长度算出来，按图层分组」。
涉及计算的都会回给你算式和结果，不是拍一个数。

5.4 上传文件 / 图片 → CAD（描摹）

  1. 点「上传文件」，选一张平面图图片或 PDF。
  2. 说：「把这张图里的墙体线条描成多段线」。
  3. 它会走描摹通道：色块分区 → 取边界 → 拟合成线。
  4. 档位建议 2–12 档；高色阶（≥16）块数会衰减，这是已知限制。

5.5 文件通道：成千上万个点

把 CSV 交给它：「读这个文件的高程点，全部建到 PW 图层」。
这种量级的活走文件通道，不会把几万个点塞进对话，速度和稳定性都好得多。

5.6 工作流：干过一次，下次带新参数重跑

  1. 第一次：说「选中这排圆，往外偏移 50」。它跑完，记录自动存进「工作流」。
  2. 打开工具页签 → 工作流 → 选中那条记录。
  3. 点「回放」→ 出现绑定表：`distance = 50` 这类槽位，改你要的值。
  4. 点「开始回放」→ 逐条确认 → 跑完。
两条硬规矩
  • 必须在同一张图里回放：记录里的句柄只在那张图有效，换图会被拦下（提示会告诉你哪张图 vs 哪张图）。
  • 槽位不能空着：空着就阻断，不会偷偷用旧值。

5.7 撤错了一步

  1. 工具页签 →「撤回上次」进入动作账本。
  2. 找到那一步（默认按时间倒序，最新的在上面）。
  3. 右键 →「撤回这一条」，或选中后点按钮。
  4. 它只撤这一条，旁边的动作不受影响；状态行会报「恢复 N · 删除 M」。

撤不回的（purge / 脚本 / Civil 3D 对象）会标「不可撤」并给原因，不会假装成功。

5.8 把公司规范喂给它

  1. 「更多 → 知识源设置（只读引用）」→ 添加你的规范文件夹。
  2. 之后提问会自动引用：「按我们公司的图层命名规则，这层应该叫什么？」
  3. 只读：它不会修改、移动、复制你的源文件。

5.1 Draw something

  1. Select objects in CAD (or select nothing and let it search).
  2. Say: "put a 100-diameter circle at every vertex of these polylines".
  3. Watch the tools pane: `getSelection` → read vertices → `createCircle` one by one.
  4. Not happy? "make the diameter 60" — it redraws or edits.

5.2 Batch by layer

"Colour everything on layer GC-DGX as colour 3, and tell me which points have z=0."
It inspects the layer with analyzeLayer first and then picks the filter — faster than clicking one by one.

5.3 Quantities

"Area and elevation range of this surface" · "total length of these lines, grouped by layer".
Actual computations come back with the formula and the number, not a guess.

5.4 Upload files or images → CAD (tracing)

  1. Press "Upload" and pick a plan image or PDF.
  2. Say: "trace the wall lines in this image into polylines".
  3. It uses the trace pipeline: colour regions → boundaries → fitted lines.
  4. 2–12 levels is the sweet spot; at 16+ levels the block count falls off — a known limit.

5.5 File channel: tens of thousands of points

Hand it a CSV: "read the point file and create them all on layer PW".
That volume goes through the file channel — it never floods the chat, and it is far faster and steadier.

5.6 Workflows: run it once, re-run with new numbers

  1. First run: "select this row of circles, offset them outward by 50". The record is saved automatically.
  2. Tools pane → workflows → pick that record.
  3. Press "Replay" → the binding table appears (`distance = 50` and friends). Edit the values.
  4. Press "Start replay" → approve step by step → done.
Two hard rules
  • Replay in the same drawing: handles only mean something there. Another drawing is refused, and the message names both files.
  • A slot cannot be left empty: an empty slot blocks the run instead of quietly reusing the old value.

5.7 Revert one wrong step

  1. Tools pane → "Undo last" opens the action journal.
  2. Find that step (newest first).
  3. Right-click → "Revert this step", or select and press the button.
  4. Only that action is undone — its neighbours are untouched; the status line reports "restored N · erased M".

What cannot be reverted (purge / scripts / Civil 3D objects) is marked "cannot be reverted" with the reason, never a fake success.

5.8 Feed it your company standards

  1. "More → Knowledge sources (read-only)" → add your standards folder.
  2. Then ask: "under our layer naming rule, what should this layer be called?"
  3. Read-only: your source files are never modified, moved or copied.

6 能力边界与已知限制6 Limits

这一章是用来减少误会的：下面每一条都是设计如此，不是 bug。

6.1 版本与运行环境

  • AutoCAD 2025 / 2026（装了 Civil 3D 则含全套专业能力）；2024 及更早不支持（运行时不同）。
  • 只支持 64 位 Windows 10 / 11。

6.2 撤销的范围

  • 只对普通 AutoCAD 图元承诺：线 / 多段线 / 圆 / 弧 / 文字 / 点 / 块参照。
  • Civil 3D 对象（路线 / 曲面 / 廊道 / 管网）标 unsupported-object，不做快照。
  • purge / 执行脚本 / 写文件这类无逆操作，标 no-inverse，不假装能撤。
  • 账本随图纸走：换图清空；条目上限 200，快照对象上限 500，超了标 expired。
  • 恢复出来的对象是新句柄；引用了旧句柄的后续动作会被标 handle-stale。

6.3 工作流回放的边界

  • 不能跨图纸：句柄属于单张图。换图后引用外源句柄的步骤被拦下。
  • 记录里本来就失败的步骤不会回放（那是缺陷痕迹，不是指令）。
  • 本地工具（读知识库之类，不走 CAD）不算可回放步骤。
  • 回放分档：A 只读（自动跑）/ B 可逆写（要确认，信任足可批量）/ C 破坏性（永远逐步确认）。
  • 槽位（换参数）只认数值 / 名称 / 路径；句柄永远是对象绑定，不是槽位。

6.4 描摹（图片 → 矢量）的边界

  • 适合：色块清晰、比例约定明确的平面图 / 立面图。
  • 高色阶（≥16 档）块数会衰减：档位越高每档区域越小，容易被吸收或丢弃。建议 2–12 档。
  • 结果会如实回报 `requestedLevels` / `effectiveLevels` 与告警，不会假装满档。
  • 手绘图、低对比度扫描件效果有限。

6.5 文件读写边界

  • 导出全盘放行：你明说路径就写到哪（那是你的成果）。
  • 导入限定目录：只允许用户目录、程序目录和 exchange\import；网络路径要先映射盘符。
  • 敏感路径（config.json、.env、密钥文件、.git）禁止写。
  • 读被 CAD / Word 占用的文件走共享读，不会因为锁住就失败。

6.6 方法与能力

  • 14 个方法底层走命令通道（托管 API 缺口）：10 个投递即返回、拿不到同步结果（render / undo / redo / 数据快捷方式 / SSA 等），3 个可回读（setVisualStyle / selectByCriteria / selectEntities），runLisp 按设计不返回值；带 25 秒超时兜底。fillet / chamfer / stretch / dimAngular / sectionPlane / convertTo* 已改为几何自研或真 API，同步返回；trim / extend / overkill 的命令版**已停投命令**，请用 trimEntityGeo / extendEntityGeo / overkillGeo。
  • 全量方法清单以面板「方法目录」或 listMethods 为准（当前 426 个）。

6.7 性能与大图纸

  • 大图纸有分页 / 本地聚合 / 上下文压缩，不会把整张图塞给模型。
  • 一次返回结果过大会自动降级为"结构化画像 + 让你取全量"，避免撑爆上下文。
  • Civil 3D 的"内部再生"（比如廊道曲面首次构建）可能几十秒到几分钟，属正常，不要强杀。

6.8 交互式命令

  • 少数命令型方法在命令行等输入时会卡住；插件有看门狗自动关对话框并解锁，但个别交互路径无法保证。
  • 真卡住了：面板「重启服务」，或命令行 C3DMCPSTOP 后重启 CAD。

This chapter exists to prevent misunderstandings: everything below is by design, not a bug.

6.1 Version and runtime

  • AutoCAD 2025 / 2026 (with Civil 3D installed, the full civil toolkit is available); 2024 and earlier are not supported (different runtime).
  • 64-bit Windows 10 / 11 only.

6.2 What undo covers

  • Only plain AutoCAD entities: line / polyline / circle / arc / text / point / block reference.
  • Civil 3D objects (alignment / surface / corridor / pipe network) are marked unsupported-object; no snapshot is taken.
  • purge, scripting and file writes have no inverse — marked no-inverse instead of pretending.
  • The journal follows the drawing: switching drawings clears it. Caps: 200 entries / 500 snapshot objects; beyond that entries are marked expired.
  • A restored object comes back with a new handle; later actions referencing the old one are marked handle-stale.

6.3 Workflow replay limits

  • Not across drawings: handles belong to one file; steps reading foreign handles are blocked.
  • Steps that already failed in the record are not replayed.
  • Local tools (reading the knowledge base and the like) are not replayable CAD steps.
  • Tiers: A read-only (runs itself) / B reversible write (confirm; trust may allow batches) / C destructive (always step by step).
  • Slots cover numbers / names / paths only; a handle is an object binding, never a slot.

6.4 Tracing limits (raster → vectors)

  • Good for clean colour blocks with a known scale: plans, elevations.
  • At 16+ levels the block count falls off; 2–12 levels is the sweet spot.
  • Results report `requestedLevels` / `effectiveLevels` and warnings honestly.
  • Hand drawings and low-contrast scans are hit and miss.

6.5 File boundaries

  • Export is open: say a path, it writes there (your output).
  • Import is restricted to the user folder, the program folder and exchange\import; network paths need a mapped drive.
  • Writes to sensitive paths (config.json, .env, key files, .git) are refused.
  • Files locked by CAD or Word are read with sharing — a lock does not fail the read.

6.6 Methods

  • 14 methods fall back to the command channel (managed-API gaps): 10 dispatch a command and return "queued" with no synchronous result (render / undo / redo / data shortcuts / SSA), 3 can be verified (setVisualStyle / selectByCriteria / selectEntities), and runLisp returns nothing by design; a 25 s timeout guard applies. fillet / chamfer / stretch / dimAngular / sectionPlane / convertTo* are now custom geometry or real API calls and return synchronously; the command versions of trim / extend / overkill no longer dispatch anything — use trimEntityGeo / extendEntityGeo / overkillGeo.
  • The authoritative list is the "method catalog" or listMethods (426 at the moment).

6.7 Performance on large drawings

  • Pagination, local aggregation and context compression keep a whole drawing out of the model prompt.
  • An oversized result degrades to a structured profile plus "ask for the full set" instead of blowing the context.
  • Civil 3D internal regeneration (first corridor surface build, say) can take from tens of seconds to minutes. That is normal — do not kill it.

6.8 Interactive commands

  • A few command-style methods can stall while the command line waits for input. The watchdog closes the dialog and unlocks, but not every interactive path can be guaranteed.
  • If it truly hangs: "Restart" in the palette, or C3DMCPSTOP then restart Civil 3D.

7 常见问题与日志7 FAQ & logs

7.1 面板弹不出来

  • 命令行输 HANK_SHOW 看有没有反应。
  • 没反应 → 插件没加载：检查 CAD 版本是否 2025/2026；重装一次；看 plugin.log 有没有加载错误。
  • 有反应但面板在屏幕外 → 用命令行 HANK_TOOLS 再试，或重启 CAD。

7.2 状态显示「离线」

  • 点「端口」看 19876 有没有监听；没有就点「重启服务」。
  • 还不行 → 看 server\relay-launcher.log（服务反复重启的原因通常在这里）。
  • 端口被别的程序占了 → 诊断窗口会标出来，改用别的端口后重启服务。

7.3 调用超时 / 一直转圈

  • 先看是不是 Civil 3D 自己在忙（大曲面、廊道再生）。
  • 任务卡住 → 点「取消任务」；再不行「重启服务」。
  • 反复超时 → 把 exchange\trace\trace-YYYYMMDD.jsonl 最近几十行发出来，能直接定位是哪一步。

7.4 模型报错

现象多半是怎么办

429请求太频等一会儿；或换一家
404 / 模型不存在模型名写错，或该账号没开通重新选模型

7.5 中文显示成乱码 / 问号

  • 先确认是不是控制台渲染问题（Windows 控制台对 UTF-8 支持差）。
  • 面板里乱码：把界面语言切一次再切回来；仍乱 → 把那份文件发给支持。

7.6 强杀 CAD 后弹出「图形修复」

强杀后再次启动 CAD 会弹图形修复窗口，它会挡住命令执行。关掉那个窗口即可（选"否"或直接关闭）。

7.8 技术支持

项目主页：github.com/Jjo37/new-acad（问题请走 Issues，附上 7.7 的材料）。

7.1 The palette will not open

  • Type HANK_SHOW in the command line.
  • No reaction → the plugin is not loaded: check Civil 3D is 2025/2026, reinstall, and read plugin.log.
  • Reacting but off-screen → try HANK_TOOLS, or restart CAD.

7.2 Status says "Offline"

  • Press "Ports" and check 19876; if nothing listens, press "Restart".
  • Still down → read server\relay-launcher.log (that is where repeated restarts explain themselves).
  • Port taken by another program → the dialog flags it; change the port and restart.

7.3 Timeouts / endless spinner

  • First check whether Civil 3D is busy itself (big surface, corridor rebuild).
  • Task stuck → "Cancel task"; if that fails, "Restart".
  • Repeated timeouts → send the last lines of exchange\trace\trace-YYYYMMDD.jsonl; that pinpoints the step.

7.5 Garbled Chinese / question marks

  • Rule out the console first: Windows consoles render UTF-8 badly.
  • Garbled inside the palette: switch the UI language away and back; if it persists, send the file to support.

7.6 "Drawing recovery" after killing CAD

If Civil 3D was killed, the next start shows a drawing-recovery window that blocks command execution. Close it (choose No, or just close the window).
